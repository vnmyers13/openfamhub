# Release 1.01 — 2026-10-13

**Tag:** `v1.01` (created by `scripts/deploy.sh publish` in CI)
**Images:** `forgejo.vernonmyers.cloud/vernon/openfamhub-{api,web}:1.01` (amd64 + arm64)
**Since:** 0.30 (2026-10-05). Builds 0.31–0.99 were published to `test` one by one; this is the first release that collects them. Build 1 failed to publish (a script lost its executable bit), so 1.01 is the first 1.x build.

Release 1.01 adds chores, routines, to-dos and points; a photo and video slideshow
for the wall, with a sleep schedule; correct handling of repeating calendar
subscriptions; and a round of security and reliability fixes from the code
review. CI now scans every build for vulnerabilities and keeps Forgejo issues in
step with the roadmap.

**Release names:** build 100 is named **1**, not 0.100. The next builds are 1.01,
1.02 … 1.99, then 2. Earlier builds keep their names (0.5, 0.99).

## What's new

### Chores, routines and to-dos (Phase 5)
- Chores that repeat every few days, on chosen weekdays or monthly, assigned to someone or up for grabs. Members claim them, mark them done (or undo) and earn points.
- Points go into an append-only ledger, ready for rewards. Each person sees their points, streak and week; everyone sees the family table.
- Routines (morning, bedtime): ordered steps with a few minutes each; the wall shows the current step with a countdown.
- A shared to-do list with an optional person and due date.
- Admins see today's chores by person and a history of who did what.
- Fixed while porting from the retired 0.29 line: chores earn points exactly once, "every 3 days" stays every 3 days, due dates follow the family's timezone, only the assignee (or an admin) can claim an assigned chore, and a chore can't be created twice for one day.

### Wall essentials (Phase 3b)
- **Photos & videos:** members upload them on the Photos page; the idle wall shows each one full screen before any repeats. Photos lose their location data; videos are converted for smooth playback on a Raspberry Pi with all metadata removed. Originals aren't kept.
- **Sleep schedule:** wall screens go dark overnight, in the family's timezone, and wake on touch.
- **Admin › Settings:** change the family name, timezone and sleep schedule after setup.
- **Off-host backups:** `backup-offhost.sh` copies database snapshots and photos to a NAS or another disk.

### Calendar subscriptions (Phase 3)
- Cancelled, moved and extra instances of repeating events are honoured; a moved instance no longer appears twice.
- Repeating events keep their local time across daylight-saving changes.
- Times without a timezone are read in the family's timezone. New installs default it to the device's zone instead of UTC.
- Adding a calendar fails straight away, with the reason, if its first sync fails.
- Only events from 90 days ago to a year ahead are stored.

### Review fixes (0.31–0.73)
- Walls update live after scheduled syncs, roll over at midnight, show events that cross midnight on both days, and return to the pairing screen when revoked.
- Pages load on demand: the first download is about 45% smaller.
- Viewers don't see "New Event"; admin pages are hidden from members; concurrent password prompts no longer hang.
- One family per install, enforced by the database; sign-in only offers that family's members.

### CI and release process (0.95–1.01)
- A Trivy scan of each published build, with HIGH/CRITICAL findings opened as issues and closed once fixed. The scanner is a pinned image, not `trivy-action` (CVE-2026-33634).
- Issues close automatically once TODO.md marks their work done, and a pinned **Triage report** issue lists open issues by priority and anything TODO.md hasn't scheduled. See [docs/releasing.md](../releasing.md).

## Security
- The photo folder was readable without signing in at `/photos/…`. That route is gone; media is served only to signed-in members and paired walls.
- Calendar-feed fetches are protected against SSRF and DNS rebinding, and feeds over 10 MB are refused.
- Admins can't create undeletable "internal" calendars; event reads check the event's own family.

## Upgrading from 0.30

Back up first ([deployment.md §7](../deployment.md#7-backups-and-restore)). Then upgrade the usual way: CI does it on the `test` VM; elsewhere run `scripts/deploy.sh publish` and `scripts/deploy.sh remote <host>`, or `scripts/deploy.sh update` for a source install.

1. **Migrations 006–008 run at startup** (one family per install, media, chores). No configuration changes are needed.
2. **The API image is about 70 MB larger** (ffmpeg and Pillow for photos and videos).
3. **Reverse proxy upload size:** if a proxy in front of OpenFamHub limits request bodies (nginx defaults to 1 MB), raise it for video uploads, e.g. `client_max_body_size 500m`. Caddy has no limit.
4. **Check the family timezone** under **Admin › Settings**. Installs set up before 0.78 defaulted to UTC, which shifts subscribed events that have no timezone. After changing it, press **Sync Now** on each calendar.
5. **Off-host backups:** set up `backup-offhost.sh` if you want copies on a NAS ([deployment.md](../deployment.md#off-host-copies-nas)).
6. **Reload wall displays** once (reboot the Pi or refresh), so they pick up the new web app.
7. **Pinned versions:** if anything pins `OPENFAMHUB_VERSION` or matches tags like `v0.*`, note that tags now run `v0.99`, `v1.01`, `v1.02` (build 1 was never published).
8. **CI secrets (optional):** add `ISSUES_TOKEN` (Forgejo token with issue read/write) to turn on Trivy issues, automatic closing and the Triage report. `TRIVY_ISSUE_TOKEN` also works.
