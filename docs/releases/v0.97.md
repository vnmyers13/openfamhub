# Release v0.97 — 2026-10-13

> Superseded by [Release 1.01](v1.01.md). Since 0.98 the issue token secret is `ISSUES_TOKEN` (`TRIVY_ISSUE_TOKEN` still works), and fixed Trivy findings close themselves.

**Tag:** `v0.97` (created by `scripts/deploy.sh publish` in CI)
**Images:** `forgejo.vernonmyers.cloud/vernon/openfamhub-{api,web}:0.97` (amd64 + arm64)

## What's in it

CI now scans every published build for known vulnerabilities with Trivy. This
release reworks the scan job first added in 0.96, which wouldn't have worked as
written. The app itself is unchanged since 0.94; upgrading a running install is
optional.

- The `trivy` job scans the exact `0.<n>` images `publish` pushed, shows a
  HIGH/CRITICAL table in the job log and uploads the JSON reports (`trivy-reports`
  artifact, 30 days). It's non-blocking: findings or scanner problems never fail CI
  or delay `deploy`.
- Optional backlog issues: set the `TRIVY_ISSUE_TOKEN` secret (Forgejo token with
  issue read/write) and each HIGH/CRITICAL finding gets one issue. Closed issues stay
  closed; at most 20 new issues per run.
- The scanner is the pinned `aquasec/trivy:0.69.3` image, not `trivy-action`
  (see CVE-2026-33634).

Details and troubleshooting: [docs/ci.md](../ci.md#trivy-scan). Full list:
[CHANGELOG.md](../../CHANGELOG.md).

## After upgrading

1. Optional: add `TRIVY_ISSUE_TOKEN` under **Settings → Actions → Secrets**.
2. Check the first `trivy` run's log. If the upload step fails, the Forgejo
   instance doesn't support `actions/upload-artifact@v4`; the log table still has
   the findings.
